# ChronoDraftAEx 使用说明

> 面向人类开发者与 AI Agent 的项目记忆系统。

---

## 本次更新：大项目模式

这次更新把旧的“全量索引”思路改成了**项目脚手架模式**。

核心变化：

- 首次接入项目时使用 `scaffold_project()`
- 不再调用 AI 去一次性总结整个代码库
- 图谱改为目录/文件/知识条目的分层结构
- 支持目录节点折叠/展开
- 扫描与 AST 分析会遵守 `.gitignore`
- Git 历史导入只记录 commit 元数据，不重做历史 AST

目的很简单：**让 ChronoDraft 在大项目上成为助力，而不是负担。**

---

## 第一部分：桌面应用

### 1. 启动前准备

```powershell
$env:CHRONODRAFT_AI_KEY="sk-你的-api-key"
$env:CHRONODRAFT_AI_BASE="https://api.openai.com/v1"
$env:CHRONODRAFT_AI_MODEL="gpt-4o"
```

说明：

- 没有 API Key 时，AI 摘要相关能力不可用
- `scaffold_project()` 仍然可以正常工作，因为它本身不依赖 AI

### 2. 启动应用

```powershell
.\dev.ps1
```

或：

```bash
cd src
wails3 dev
```

### 3. 仪表盘

#### 初始化项目脚手架

首次接入项目时，在仪表盘点击“构建项目脚手架”。

系统会执行：

1. 扫描文件结构
2. 预计算 AST
3. 导入最近 Git 历史
4. 让 Agent 之后可以通过 `get_snapshot()` 获取项目快照

这个流程是零 AI 成本的。

#### 日常使用

- 搜索知识条目
- 查看最近变更
- 在需要时通过 `get_snapshot()` 获取最新项目快照

### 4. 知识图谱

图谱现在主要展示：

- 目录（directory）
- 文件（file）
- 知识条目（entry）
- 标签（tag）

支持：

- 力导向拖拽
- 目录节点双击折叠/展开
- 更适合大项目的分层浏览

### 5. 代码结构

代码结构页展示预计算的 AST 实体：

- 函数
- 类型
- 导入
- 其他可识别结构

这些数据来自脚手架初始化与后续增量更新。

## 第二部分：Agent / MCP 使用

### 1. 构建 MCP 服务器

```bash
cd src
go build -o chronodraft-mcp.exe ./cmd/mcp
```

### 2. 环境变量

| 变量 | 说明 |
|:---|:---|
| `CHRONODRAFT_PROJECT_ROOT` | 被监控项目根目录 |
| `CHRONODRAFT_AI_KEY` | AI Key |
| `CHRONODRAFT_AI_BASE` | AI Base URL |
| `CHRONODRAFT_AI_MODEL` | 对话模型 |

### 3. 首次接入项目

```text
scaffold_project()
```

它会：

- 扫描结构
- 建图
- 预计算 AST
- 导入最近 Git 历史
- 让 Agent 后续通过 `get_snapshot()` 获取快照

它不会：

- AI 总结整个仓库
- 生成“全量索引”的巨型知识条目

### 4. 日常工作流

#### 修改前

```text
get_context(files="src/foo.ts")
```

#### 修改后

```text
record_change(
  what: "改了什么",
  why: "为什么这样改",
  problem: "解决了什么问题",
  files: "相关文件",
  tags: "关键词"
)
```

#### 搜历史

```text
search_knowledge(query="认证模块", top_k=5)
```

#### 看关系

```text
get_graph(query="用户模块", top_k=5)
```

### 5. 关键工具说明

#### `scaffold_project`

首次接入项目时使用。

- 零 AI 调用
- 初始化结构和上下文
- 适合大项目

#### `record_change`

这是唯一的高层知识入口。

代码 diff 能说明“改了什么”，但只有 `record_change` 能说明“为什么这样改”。

#### `capture_commit`

通常由 Git Hook 自动调用。

#### `get_code_entities`

读取已经预计算好的 AST 结果，不需要实时重新分析整个项目。

## 故障排查

| 问题 | 原因 | 解决方案 |
|:---|:---|:---|
| 图谱太乱 | 目录未折叠 | 在图谱中双击目录节点进行折叠 |
| AST 数据为空 | 尚未初始化脚手架 | 先执行 `scaffold_project()` |
| 搜索结果少 | 没有记录高层决策 | 增加 `record_change()` 调用 |
| 脚手架扫描太慢 | 项目过大且忽略规则不足 | 检查 `.gitignore` 是否覆盖生成目录 |

---

## 一句话理解

ChronoDraftAEx 现在的定位很明确：

**初始化时建立结构，开发中持续记录决策，而不是替你一次性“理解整个项目”。**
